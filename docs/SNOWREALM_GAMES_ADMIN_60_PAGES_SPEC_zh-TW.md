# SnowRealm Games｜管理後台 60 個主功能頁面完整需求規格（GA-01～GA-60）

> 文件用途：ChatGPT Work / Claude Code / 前後端工程、UI 設計、產品驗收之統一交接文件。
> 版本：v1.0｜日期：2026-11-21｜狀態：**60 頁規格定案，不代表已開發完成或正式部署**。
> 範圍：**僅 SnowRealm Games**，含 SPINREALM（cube1）、BRICKDUEL（cube2）、六款 Arcade 與未來加入的 Games 產品。**不涵蓋 SnowRealm Music、Drama、Commerce 或其他事業。**

## 0. 不可覆蓋的 Owner 決策

1. **總數固定 60 個主功能頁面**，唯一編號 GA-01 至 GA-60；八大導覽模組。頁內 Tab、篩選器、抽屜、彈窗、詳情狀態不另計為主頁。
2. 後台網址不得使用 `admin.snowrealm.pet`。規劃在 `https://games.snowrealm.pet/<RANDOM_GAMES_CONSOLE_PATH>/` 下提供受保護入口；**正式 route 尚未部署**。舊 `/admin/` 持續退役。
3. 正式管理前端須與公開玩家 `dist/` 分離，受 Cloudflare Access／同級身份閘門與 MFA 及私有 origin 防繞過保護；後端每一請求再驗 JWT、allowlist、RBAC。亂數路徑不等於密碼。
4. **cube1 / cube2 repo、資料庫、金幣、道具、段位、對局、訂閱彼此隔離**。跨遊戲只交換被允許的統計或平台玩家身份關聯，不直接連對方資料庫。
5. 初版玩家資產、停權、退款、資料刪除、會員權益等高風險操作**唯讀或申請審核**。任何寫入、不可逆操作、正式金流／付費開通須符合權限、二次確認、稽核及 Owner 授權。
6. 正式 Identity、OAuth、跨裝置找回仍需驗證；尚未完成時畫面標示「尚未接入」。不擅自切換 cube2 的 `IDENTITY_LINK_ENABLED`。
7. 既有 `internal/admin-console/` 包含 7 個原型面板，並非 7 個正式已驗收頁；本文件的「原型」只代表存在 UI 起點。

### 建議 URL 規則

- `ADMIN_BASE = https://games.snowrealm.pet/<RANDOM_GAMES_CONSOLE_PATH>`，所有以下 Route 都是此 Base 後面的相對路徑，不代表已部署。
- 例如 GA-01：`{ADMIN_BASE}/overview`；GA-06：`{ADMIN_BASE}/players/:playerId`。路由參數必須驗證，不得以 ID 繞過權限。
- 管理頁禁止被公開站 sitemap、搜尋索引或 PWA Service Worker 快取。從未授權瀏覽器直接開啟 HTML/JS/CSS 也應被拒絕。
- 既有管理 API 路徑 `/v1/admin/*` 是後端資料 API，**不是**此文件的頁面 Route。

## 2. 每個主功能頁面規格

頁面狀態欄位：**原型**＝已有部分 UI；**待開發**＝尚無可認定完成的正式頁面。開發階段：P0＝首版 19 頁、P1＝營運擴充 26 頁、P2＝商業化進階 15 頁。

### A｜營運戰情中心（4 頁）

#### GA-01｜總控制台首頁

- **開發階段**：P0｜**現況**：原型｜**Route**：`/overview`
- **主要功能**：平台 KPI、跨遊戲狀態、今日新增玩家、在線與故障摘要。
- **資料與依賴**：cube1 管理 overview；cube2 overview 待開發。
- **驗收重點**：來源、更新時間、數據定義清楚；異常不顯示成 0。

#### GA-02｜即時營運監控

- **開發階段**：P1｜**現況**：待開發｜**Route**：`/operations/live`
- **主要功能**：當前在線／房間／配對、延遲、錯誤率、刷新頻率。
- **資料與依賴**：遊戲伺服器狀態、WebSocket/DO、cube2 房間指標。
- **驗收重點**：離線、無資料、不可用三種狀態分明；不可虛構在線人數。

#### GA-03｜各遊戲營運比較

- **開發階段**：P1｜**現況**：待開發｜**Route**：`/operations/games`
- **主要功能**：旋界、轉磚及 Arcade 的活躍、對局、留存比較。
- **資料與依賴**：依各遊戲可用指標整合，不混用不同統計口徑。
- **驗收重點**：標示每款遊戲統計來源及可比性；支援日區間。

#### GA-04｜異常警示中心

- **開發階段**：P0｜**現況**：待開發｜**Route**：`/operations/alerts`
- **主要功能**：服務故障、認證異常、經濟違規風險、未解決事件。
- **資料與依賴**：平台監控事件、Identity 服務告警、跨遊戲 API。
- **驗收重點**：分級、來源、時間、處理人與稽核；告警不得自動觸發危險寫入。

### B｜玩家管理與 CRM（9 頁）

#### GA-05｜玩家列表

- **開發階段**：P0｜**現況**：原型｜**Route**：`/players`
- **主要功能**：查詢、篩選、狀態、建立時間、來源遊戲、分頁。
- **資料與依賴**：cube1 /v1/admin/players；cube2 players 待實作。
- **驗收重點**：非管理員不能查；敏感欄位不返回；分頁上限有效。

#### GA-06｜玩家 360° 詳情

- **開發階段**：P0｜**現況**：待開發｜**Route**：`/players/:playerId`
- **主要功能**：基本資料、遊戲進度摘要、金幣與交易、訂閱、近期事件。
- **資料與依賴**：平台 ID 映射、各遊戲唯讀玩家詳情。
- **驗收重點**：跨遊戲身份未連結時不強行合併；無權看敏感資料。

#### GA-07｜平台身分與裝置

- **開發階段**：P0｜**現況**：待開發｜**Route**：`/players/:playerId/identity`
- **主要功能**：SnowRealm 平台 UUID、綁定狀態、裝置與換機找回稽核。
- **資料與依賴**：Identity 映射與各遊戲裝置摘要；未部署部分留空。
- **驗收重點**：僅顯示可用身分資料；不可顯示 Token/裝置密鑰。

#### GA-08｜客服工單中心

- **開發階段**：P1｜**現況**：待開發｜**Route**：`/crm/tickets`
- **主要功能**：工單、分類、優先級、分派、回覆與 SLA。
- **資料與依賴**：Games 專用客服資料庫與權限。
- **驗收重點**：工單修改留痕；玩家資料按工單最小揭露。

#### GA-09｜檢舉與申訴

- **開發階段**：P1｜**現況**：待開發｜**Route**：`/crm/reports`
- **主要功能**：作弊檢舉、申訴、附件／證據、裁決覆核。
- **資料與依賴**：客服工單、有效對局證據。
- **驗收重點**：不得把「玩家回報結果」冒充伺服器證明。

#### GA-10｜停權與處分管理

- **開發階段**：P2｜**現況**：待開發｜**Route**：`/crm/moderation`
- **主要功能**：停權記錄、處分原因、期限、審核及申復。
- **資料與依賴**：Identity／各遊戲停權紀錄與審計。
- **驗收重點**：第一階段僅讀；寫入需二次驗證、分級權限與覆核。

#### GA-11｜個資與刪除請求

- **開發階段**：P1｜**現況**：待開發｜**Route**：`/crm/privacy-requests`
- **主要功能**：查閱、匯出、更正、刪除、恢復期與處理期限。
- **資料與依賴**：身份服務和各遊戲資料請求登記。
- **驗收重點**：30×24h 恢復規則只適用已核准範圍，不跨遊戲擅刪。

#### GA-12｜玩家訊息管理

- **開發階段**：P2｜**現況**：待開發｜**Route**：`/crm/messages`
- **主要功能**：站內訊息、系統通知、客服模板與發送審核。
- **資料與依賴**：通知服務／玩家同意偏好。
- **驗收重點**：拒收與同意條件生效；批次發送需審核。

#### GA-13｜玩家分群與標籤

- **開發階段**：P1｜**現況**：待開發｜**Route**：`/crm/segments`
- **主要功能**：新進、活躍、回流、流失、會員等客群。
- **資料與依賴**：合法取得的行為資料和匿名統計。
- **驗收重點**：群組規則透明；避免使用敏感推測資料。

### C｜遊戲營運管理（10 頁）

#### GA-14｜遊戲管理列表

- **開發階段**：P0｜**現況**：待開發｜**Route**：`/games`
- **主要功能**：遊戲清單、開發狀態、版本、渠道、負責團隊。
- **資料與依賴**：Games 目錄、部署版本、cube2 對接資訊。
- **驗收重點**：不能把概念頁標為可玩；支援來源與狀態篩選。

#### GA-15｜遊戲設定與功能開關

- **開發階段**：P1｜**現況**：待開發｜**Route**：`/games/:gameId/settings`
- **主要功能**：功能旗標、實驗配置、版本適用範圍、灰度控制。
- **資料與依賴**：各遊戲獨立的受控設定服務。
- **驗收重點**：危險開關需變更理由及批准；禁止自動啟用 Identity 綁定。

#### GA-16｜對局紀錄

- **開發階段**：P0｜**現況**：原型｜**Route**：`/games/matches`
- **主要功能**：對局條件搜尋、玩家、模式、結果、時間。
- **資料與依賴**：cube1 /v1/admin/matches；cube2 matches 待實作。
- **驗收重點**：說明不同遊戲「一場」的計數單位，避免假定同口徑。

#### GA-17｜對局詳情與爭議

- **開發階段**：P1｜**現況**：待開發｜**Route**：`/games/matches/:matchId`
- **主要功能**：結算細節、伺服器驗證、申訴關聯與證據。
- **資料與依賴**：遊戲自有對局資料與校驗紀錄。
- **驗收重點**：來源不足時標「無伺服器證據」，不自稱已回放。

#### GA-18｜多人房間與配對

- **開發階段**：P1｜**現況**：待開發｜**Route**：`/games/multiplayer`
- **主要功能**：等待隊列、房間狀態、斷線與多伺服器狀態。
- **資料與依賴**：cube1 Workers/DO、cube2 room/queue。
- **驗收重點**：匿名或個資資料僅顯示必要摘要。

#### GA-19｜排行榜管理

- **開發階段**：P1｜**現況**：待開發｜**Route**：`/games/leaderboards`
- **主要功能**：排名、季節、異常記錄、榜單版本。
- **資料與依賴**：各遊戲排行榜來源。
- **驗收重點**：榜單只讀先上，修改名次需另行核准。

#### GA-20｜賽季與排位管理

- **開發階段**：P1｜**現況**：待開發｜**Route**：`/games/seasons`
- **主要功能**：賽季時程、分段、規則、結算狀態。
- **資料與依賴**：各遊戲排位規格與結算資料。
- **驗收重點**：不可把旋界伺服器排位規則直接套到轉磚 AI 排位。

#### GA-21｜反作弊與風控

- **開發階段**：P1｜**現況**：待開發｜**Route**：`/games/anti-cheat`
- **主要功能**：可疑對局、重放、頻繁請求、篡改和風險處理。
- **資料與依賴**：伺服器權威事件與安全日誌。
- **驗收重點**：證據／疑似／已確認三種標籤分明。

#### GA-22｜任務與成就管理

- **開發階段**：P1｜**現況**：待開發｜**Route**：`/games/quests`
- **主要功能**：每日任務、觸發條件、上限、成就、獎勵。
- **資料與依賴**：現有任務規格與各遊戲可驗證事件。
- **驗收重點**：獎勵不得由客戶端直接宣稱完成。

#### GA-23｜活動與賽事管理

- **開發階段**：P2｜**現況**：待開發｜**Route**：`/games/events`
- **主要功能**：活動、競賽、報名、獎勵審核。
- **資料與依賴**：各遊戲活動表與公告系統。
- **驗收重點**：發獎與規則變更需審核，測試版不發真實資產。

### D｜遊戲經濟與商城（8 頁）

#### GA-24｜遊戲經濟總覽

- **開發階段**：P0｜**現況**：待開發｜**Route**：`/economy`

- **資料與依賴**：cube1 wallets/ledger；cube2 ledger 待 API。
- **驗收重點**：不同遊戲幣不得直接相加；可切遊戲與日期。

#### GA-25｜玩家錢包查詢

- **開發階段**：P0｜**現況**：待開發｜**Route**：`/economy/wallets`

- **資料與依賴**：各遊戲獨立只讀錢包服務。
- **驗收重點**：不能從這個頁面直接改金幣餘額。

#### GA-26｜金幣流水帳本

- **開發階段**：P0｜**現況**：原型｜**Route**：`/economy/ledger`

- **驗收重點**：唯一事件與來源、交易時區、分頁一致；無法取數顯示錯誤。

#### GA-27｜商城商品管理

#### GA-28｜造型與主題管理

- **資料與依賴**：各遊戲外觀庫、Steam 權益。
- **驗收重點**：客製圖與版權審查；跨版本顯示規則清楚。

## 4. 平台資料與後端接口規則

### 4.1 已有的 cube1 程式與介面起點

- 既有 UI 原型：`internal/admin-console/index.html`、`admin.mjs`、`admin.css`；七個面板對應本文件 GA-01、GA-05、GA-16、GA-26、GA-47、GA-56、GA-60。
- 既有管理後端：`server/api/admin.mjs`、`server/api/app.mjs`，具有管理 JWT 驗證與 `SNOWREALM_ADMIN_SUBJECTS` 伺服器白名單。
- 已定義的只讀 API：`GET /v1/admin/overview`、`/trends`、`/players`、`/ledger`、`/matches`。程式存在不等於所有功能的已授權正式 E2E 驗收完成。
- `docs/ADMIN_SECURITY_DEPLOYMENT.md` 與 `docs/SNOWREALM_GAMES_ADMIN_API_BRICKDUEL_HANDOFF.md` 是現有安全及跨遊戲介面規格。

### 4.2 cube2（Claude）資料源

- Claude 負責 `luffysky/cube2`，規格見 `docs/BRICKDUEL_ADMIN_API_ADAPTER_SPEC.md`。
- 需要的只讀端點：`/internal/admin/v1/overview`、`players`、`draws`、`matches`、`metrics`、`metrics/daily`、`players/{gameUserId}`。路徑只代表雙方契約，不能當成目前已正式可用。
- 機器身份 `aud=snowrealm:brickduel:admin`、`scope=brickduel:admin:read`、`sub=svc:snowrealm-games-admin`；機器 JWT 僅後端保管，絕不能從瀏覽器呼叫或暴露。
- `snowrealmPlayerId` 在正式綁定前可為 `null`。各種未實作或無法測量的值使用 `null`，真正量到 0 才回 `0`。
- 不把不同遊戲的同名欄位自動視作一致。特別注意《旋界》真人排位與《轉磚》排位的計數意義不同。

### 4.3 統計、CRM、ERP 共通規範

- 每個報表顯示 `source`, `gameId`, `generatedAt` 或 `fetchedAt`、時區、期間、口徑、更新時間；跨遊戲合計需確認可比較。
- 金幣是**每款遊戲自己的虛擬貨幣**；總覽可以並排，不可跨遊戲直接相加為「平台錢包」。
- 訂閱/付款/Steam/廣告收入未有正式資料來源時顯示「未啟用」或「無資料來源」，不得預填虛構營收。
- 原始玩家 Email、驗證碼、Token、雲端存檔密鑰、IP、裝置密鑰、完整 `state`/`srv` 等敏感資料不進一般管理報表。
- 幣值欄位依資料庫與契約使用安全精度（例如整數字串），不得轉為浮點損失精度。
- 跨遊戲接口失敗不可讓整個 Games 後台無法使用，但必須清楚標示哪個資料源失效。

## 5. 管理安全與權限設計

| 身分 | 可見範圍（首版建議） | 不可做的事 |
|---|---|---|
| Owner | Games 全平台管理、配置與敏感審核；任何高風險操作仍需二次確認 | 不可繞過不可逆刪除與正式密鑰安全規範 |
| Operator | Games 營運、版本、活動、指標（依細粒度授權） | 不可看私密 Token／任意刪除玩家資料 |
| Support | 經核准的玩家查詢、客服工單、申訴處理 | 不可直接改金幣、退款、停權或全量匯出 |
| Auditor | 規定範圍的唯讀稽核、報表和資安證據 | 不能寫入任何玩家資產或配置 |

安全驗收要求：Cloudflare Access／同級 MFA 先保護頁面與全部素材；直接訪問私有部署 origin 或 preview URL 不可繞過；API 每次驗 JWT/roles/audience/subject；合理限流；CSRF 防護；敏感操作二次驗證；操作原因及稽核；管理 Token 不進 URL/localStorage/console 日誌；Cache-Control no-store；供應商私鑰只在伺服器秘密管理。

## 6. 全頁 UI／UX 統一交付要求

1. **桌面版優先**：統一左側 8 模組導航、頂部 Games 品牌、環境標籤、資料來源、登入身份、更新時間。窄版至少能查看和審核，不可暴露隱藏功能。

4. **可存取性**：鍵盤操作、語意標籤、焦點、表格排序及警告文字，重要狀態不用只有顏色表示。
5. **數據真實性**：每張卡片呈現 API 來源、請求時點及錯誤狀態，沒有資料時不得使用假數字。
6. **更改權限視覺化**：唯讀、可編輯、須覆核、不可用等狀態標示清楚，前端 disabled 並非授權機制，後端必須再次檢查。
