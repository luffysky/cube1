# SnowRealmGames Web／PWA 路線與手機驗收

文件狀態：內部規劃草案。查閱日期：2026-11-18（Asia/Taipei）。

**已確認的產品限制：所有遊戲只做 Web，最多 PWA，不做原生 App。** 入口與 PWA 基礎已實作，瀏覽器功能驗收已完成；真人連線、雲端存檔、實機離線安裝與手機效能仍待後續驗收。

## 1. 現況與第一步

| 項目 | 真實狀態 | 接下來需要做什麼 |
| --- | --- | --- |
| SnowRealmGames | 遊戲館、搜尋／篩選、本機收藏與遊戲頁已完成 | 下一階段驗證公開發行、訪客體驗與回訪 |
| 旋界／SPINREALM | 已有可玩原型 | 保持既有遊戲可用；持續驗證操作、裝置與後續真人連線 |
| 52 HUNT | 規劃中 | 撲克牌身分追獵規則與小型連線測試切片 |
| NEXT FLOOR 下一層 | 規劃中 | 一個電梯 Hub＋一個可探索微型世界的垂直切片 |
| PWA | Manifest、白名單快取、登入頁拒收與自願更新已實作；12 項測試通過 | Safari／Android 安裝、發布網域的真實斷網及版本更新仍需實機驗收 |

入口可以先整合導航與介紹，不需為了看起來是平台就立即建立大型商店或第三方遊戲投稿系統。旋界既有可玩版本先維持，後續整合帳號與返回入口時再逐步遷移。

## 2. 平台共同能力

### 2.1 入口與遊戲頁

- 每款顯示實際狀態：可試玩、測試中、規劃中等。
- 可玩遊戲才提供真的遊玩入口；規劃中提供玩法介紹，不顯示假開局或假的匹配人數。
- 顯示適用操作方式，區分鍵盤、觸控及尚待驗證的裝置。
- 遊戲保持自己的視覺與互動，平台統一名稱、返回入口與帳號資訊。

### 2.2 載入與資源

入口只載入導航與展示所需資源。各遊戲拆成獨立資源包，進入後再載入；首頁不預載全部 3D 世界。

本版已採同網域路徑 `/games/spinrealm/`、`/games/52hunt/` 與 `/games/next-floor/`；後兩個目前是開發概念頁。若分網域，不假設 localStorage、登入狀態或快取自動共用。

共用登入及權益以後端服務建立；前端只保存可重新取得的偏好及快取。各遊戲以自己的規則版本與資源版本更新。

### 2.3 帳號與存檔

可以先允許訪客玩合適的單人內容。需要跨裝置進度、朋友功能或購買恢復時，再連接正式帳號。

本機 IndexedDB／Cache／localStorage 不是永久備份。瀏覽器可能清除 best-effort 資料；持久儲存請求也要處理未獲准的情況。重要雲端進度與付費權益以伺服器紀錄為準。［4］

## 3. PWA 的用途與範圍

PWA 用來改善回訪、啟動與支援範圍內的離線體驗；不把它當成原生 App 的同義詞。安裝方式依瀏覽器不同，介面必須做能力偵測與合適提示。

### 3.1 加入主畫面

建議優先提供 SnowRealmGames 平台 PWA，必要時補各遊戲捷徑。Apple 官方提供 Safari 加入主畫面及以 Web App 開啟的流程；不能假設每個瀏覽器都有同樣的自訂安裝提示。［1］

安裝入口在確認可用時才顯示相應操作；已在獨立模式運行時，不重複要求加入主畫面。

### 3.2 快取與更新

- 快取平台 shell、必要圖示與明確版本的遊戲資源。
- 對局進行中不強迫重整；更新提示等到安全的結算或主選單處理。
- 新版遊戲核心與 server 規則不相容時，阻止錯版本進房，說明更新需要。
- 清掉過期資源時保留必要回復路徑；不把刪除快取變成刪除唯一存檔。
- 分別測試首次造訪、已快取重開、更新中斷、空間不足與清除網站資料。

### 3.3 離線能力表

| 功能 | 候選離線策略 | 不可宣稱的能力 |
| --- | --- | --- |
| 平台入口 | 已快取的遊戲資訊與離線說明 | 未取得的新公告、即時好友與伺服器狀態 |
| 旋界單人／CPU | 資源與本機存檔驗收後，可離線啟動 | 本機 CPU 存在不代表目前已做完離線包 |
| 旋界真人對戰 | 需連線 | 離線匹配真人或同步戰績 |
| 52 HUNT 真人局 | 需連線；回線後依規則恢復 | 52 人真人局在無網路時照常進行 |
| NEXT FLOOR | 只對已下載、明確支援的單人內容提供離線 | 所有世界、動態事件及多人 Hub 全部離線可玩 |

### 3.4 推播與背景狀態

通知是選擇性能力。WebKit 官方說明主畫面 Web App 可請求 Web Push，且請求需由使用者操作觸發。未安裝、未授權或不支援時，站內仍能正常使用。［2］

背景頁面的繪製回呼通常暫停，計時器也可能節流。切 App 或鎖屏後，不依賴玩家裝置一直執行遊戲循環。［3］

- 單人模式：在合適情況暫停，回來後清楚恢復。
- 多人模式：伺服器維持權威時間；客戶端回來時重新同步，不把本機暫停等同全房暫停。
- 斷線處理：顯示重連狀態，依模式的寬限與勝負規則處理，避免無聲失去整局。

## 4. 三款遊戲各自的技術重點

### 4.1 旋界／SPINREALM

保留 Canvas／ES module 的可用核心，優先驗證鍵盤和觸控操作。邏輯步進、繪製與網路傳送頻率分開設計；高邏輯頻率不代表每幀都傳整張棋盤。

真人房間需要 server 掌握規則、方塊序列、合法操作、攻擊與勝負；本機即時回饋配合權威校正。先做朋友 1v1 與重連，再擴配對及多人。

### 4.2 52 HUNT

52 人、16 鬼／36 人、60 秒保護與 Joker 任務是目前企劃範圍。需要分清楚：

1. 伺服器知道的完整身分與任務。
2. 個別玩家此刻允許知道的資訊。
3. 螢幕目前需要呈現的附近角色與世界狀態。

不能先把所有隱藏身分傳到瀏覽器，再只靠介面隱藏。身分分發、保護期、任務與勝負由 server 驗證。

若採 3D 呈現，52 人不代表每台裝置必須同時高精細繪製所有角色。使用視野／距離分級、批次繪製、模型與特效預算，並在可辨識性上保持公平。

先以小型測試確認玩法和連線，再逐步增加真實 client 驗證到 52 人。模擬 client 負載測試與 52 人真人體驗是兩種證據，分開報告。

### 4.3 NEXT FLOOR 下一層

永久電梯 Hub 是玩家持續返回的空間，電梯通往不同微型世界。首個切片只需一個 Hub 與一個有探索、互動和回程的樓層，先驗證循環是否值得再玩。

載入策略以 Hub＋當前世界為主，對將進入的資源做適量預載；離開世界後釋放不再使用的模型、貼圖、音訊與其他資源。永久進度不等於永久佔用 GPU 記憶體。

初期不承諾無限個已完成世界。「永無止境」是產品體驗方向，新增世界仍需要內容製作、測試與版本管理。

## 5. 手機 3D 的必要限制

MDN 指出 WebGL 沒有可攜的最大 VRAM 查詢能力，應保守預算、處理 context loss、降低解析度並提供畫質選擇。［5］

Chrome 官方也指出桌機 CPU 降速不能重現手機的 GPU、記憶體頻寬與熱降頻；實機測試仍是必要依據。［6］

本平台的實作方向：

- 設低／標準／高畫質，手機初始選保守設定，避免先卡住再要求使用者找設定。
- 依裝置負擔調整渲染解析度、陰影、粒子、遠距角色細節與貼圖預算。
- 優先批次繪製、共用素材、壓縮紋理與分段載入，而非只降低模型面數。
- 場景退出即釋放資源；處理 WebGL context loss 後的重建或可理解的重新載入。
- 重連、畫質調整或視窗改變不應重複發送遊戲動作或破壞存檔。
- 未支援的渲染能力給清楚的相容性畫面，入口網站仍可使用。

## 6. 實機驗收矩陣

第一輪至少包含 iPhone Safari、iPad Safari、Android 中階機 Chrome、桌機 Chrome／Edge，以及可支援的主畫面 PWA 模式。具體 OS／瀏覽器版本以測試當天紀錄為準。

| 測項 | 方法 | 通過的意義 |
| --- | --- | --- |
| 首次載入 | 未快取、一般行動網路條件 | 首次進入可理解，有載入進度及失敗回復，不需先下載全部遊戲 |
| 回訪與快取 | 關閉後重開、離線重開 | 只顯示實際可離線的能力，不用空白畫面代表斷網 |
| 長時間效能 | 實機連續遊玩，記錄幀時間與發熱 | 判斷是否需要降低畫質；一次截圖不能證明效能 |
| 觸控 | 多點操作、邊緣手勢、橫直向 | 必要按鈕可達，遊戲不被誤滾動或瀏覽器手勢干擾 |
| 安全區 | 瀏海、動態工具列、主畫面模式 | 關鍵按鈕與狀態沒有被遮住 |
| 音效 | 首次點擊啟動、暫停、返回 | 不假設 autoplay 一定成功；恢復不重疊播放 |
| 背景與鎖屏 | 切 App、鎖屏、返回 | 單人暫停合理，多人重新同步且告知結果 |
| 網路切換 | Wi-Fi／行動網路切換與短斷線 | 重連後棋盤、任務、計時與權威結果一致 |
| 資源不足 | 降畫質、context loss、儲存失敗 | 可回復或清楚引導，不假裝存檔與購買已成功 |
| 更新 | 舊快取遇到新資源／server | 不混用不相容規則，不在對局中無預警刷新 |

可先以「3D 中階手機穩定 30 fps、能力足夠的裝置提升到 60 fps」作為待確認的工程目標；旋界則優先觀察輸入反應與幀時間穩定性。這些是目標，不是目前已測結果，也不保證所有裝置均支援。

## 7. 開發里程碑與必要證據

| 階段 | 重點 | 必須留下的證據 |
| --- | --- | --- |
| W0：入口 | 真實遊戲狀態與連結 | 桌機／手機導航可用；旋界可開啟；規劃遊戲沒有假開局 |
| W1：旋界穩定性 | 操作、觸控、重試 | 可重現的測試案例、裝置條件、錯誤修正 |
| W2：朋友 1v1 | 房間、對局、重連 | 兩台真實瀏覽器開局至結算；斷線後能依規則復原 |
| W3：平台帳號 | 基礎進度與權益 | 訪客／登入切換、跨裝置恢復、錯誤狀態正確 |
| W4：PWA | 快取、更新、離線範圍 | 安裝與非安裝模式實機紀錄；各離線項目分別驗收 |
| W5：NEXT FLOOR 切片 | Hub 與一個世界的探索循環 | 進出世界、保存進度、重開恢復、手機資源管理 |
| W6：52 HUNT 切片 | 身分規則與多人負載 | 隱藏資訊不洩漏、保護期與任務正確、逐級人數測試 |
| W7：逐步擴張 | 新世界、更多多人模式 | 依玩家回饋與負載結果擴充，不先承諾無限內容或固定日期 |

階段可有獨立工作並行，但不得以介面按鈕已存在替代後端或實機驗收。商業功能另遵循 `business-model.md`，未完成金流及權益驗證前不對外販售。
