# SnowRealmGames 商業模式規劃

文件狀態：內部規劃草案。查閱日期：2026-11-18（Asia/Taipei）。

本文件區分已確認方向、候選設計與數字假設。**尚未串接金流、建立可售會員、啟用廣告收益或完成跨遊戲購買權益。** 文件內容不得直接當成對外售價、已交付功能或收入預測。

## 1. 已確認的產品範圍

| 產品 | 目前狀態 | 已確認方向 |
| --- | --- | --- |
| SnowRealmGames | 入口網站建置中 | 集中呈現自有遊戲，提供遊玩入口與真實開發狀態 |
| 旋界／SPINREALM | 已有可玩原型 | 以方塊操作手感、T-Spin、反擊與短局對戰為基礎 |
| 52 HUNT | 規劃中 | 52 人撲克牌身分追獵；16 鬼／36 人、開局 60 秒保護、Joker 任務是目前提供的玩法設定 |
| NEXT FLOOR 下一層 | 規劃中 | 永無止境的電梯通往不同世界；電梯是永久 Hub，每層是可探索的微型世界 |

所有遊戲只做 **Web**；最多延伸為 **PWA**，不規劃原生 App。52 HUNT 與 NEXT FLOOR 不能標示已上線，NEXT FLOOR 不是「404」題材。企劃設定不代表已完成平衡或技術驗證。

已可玩的旋界也不代表真人配對、正式排行、跨裝置帳號、PWA 或付費功能均已完成；每項功能依實際交付另行標示。

## 2. 商業原則

1. **免費核心**：玩家可完整理解並享受主要玩法，必要操作與競技能力不受付款限制。
2. **不賣強度**：不賣傷害、防禦、移動速度、額外情報、角色分配優勢或更有利的配對。
3. **明碼外觀**：單件或套組清楚說明內容、適用遊戲與期限；初期不需要多層虛擬幣換算。
4. **可選支持者**：以支持開發和身分展示為核心，權益必須已存在、可交付且範圍明確。
5. **廣告自願且不打斷**：單人模式可提供獎勵廣告；多人對局內不插播，不讓其他玩家等一人看廣告。
6. **先兌現再販售**：未完成的商店、會員及廣告功能只能標示規劃，不模擬真實交易成功。

「外觀」不自動等於公平：更難辨認的服裝、干擾對手的閃光或會拖慢其他玩家裝置的特效，也可能破壞遊戲體驗。

## 3. 三款遊戲使用不同的商業重點

### 3.1 旋界／SPINREALM：免費競技＋個人表現

候選商品包括棋盤邊框、背景主題、消行音色、結算動畫與個人徽章。商品的第一個目標是讓玩家表達偏好，不是提高消行效率。

免費基礎包括 SRS 旋轉、DAS／ARR 設定、Hold、正常練習及基本對戰。不能販售更長競技鎖定時間、更少垃圾、更強攻擊、額外 Next 預覽或優先匹配弱者。

外觀效果要能關閉；對手端可採統一可讀性顯示。競技場使用相同規則，個人輸入偏好與改變遊戲能力的參數分開管理。

### 3.2 52 HUNT：免費身分博弈＋可辨識裝扮

候選商品包括不影響辨識的服裝、名牌、賽後動作與收藏卡面。出售前檢查遠距輪廓、明度、遮蔽程度與碰撞範圍，不接受付費服裝帶來隱蔽優勢。

16 鬼／36 人分配、60 秒保護、Joker 任務、情報獲取與勝負條件均不因付費而改變。不販售指定有利身分、重抽身分、延長保護、追蹤真身或任務捷徑。

現階段不預售角色或會員權益；先證明多人規則及身分資訊分發可正確運作。52 人是產品設定，不是已完成 52 人真人負載測試的宣稱。

### 3.3 NEXT FLOOR 下一層：免費探索核心＋Hub 裝飾

候選商品包括個人電梯空間裝潢、照片框、展示架、收集冊外觀與可選氛圍主題。永久 Hub 應成為玩家累積回憶與展示收藏的地方。

必要線索、基本探索能力與合作事件不能故意做得不完整，再要求玩家看廣告或付款。若未來考慮付費世界或章節，必須先完成可玩的內容、明確標示包含樓層與合作進入規則，再單獨評估；目前不納入已定案收入。

裝潢要有資源預算，避免付費擺設使同房手機掉幀。永久 Hub 表示世界設定與進度可保存，不表示伺服器程序或所有樓層資源永遠常駐。

## 4. 平台共用權益與遊戲特例

| 層級 | 建議共用內容 | 邊界 |
| --- | --- | --- |
| 平台帳號 | 暱稱、好友、平台徽章、購買紀錄、支持者狀態 | 各遊戲的成績與資源仍各自管理 |
| 平台支持者 | 個人頁主題、明確列出的展示功能、當期已完成裝飾 | 不承諾所有未來遊戲／內容永久包含 |
| 單款商品 | 以遊戲 ID＋物品 ID 記錄棋盤、服裝或 Hub 裝飾 | 買旋界外觀不自動取得另一款遊戲外觀 |
| 跨遊戲套組 | 購買前列出每款遊戲實際可用的物品 | 尚未上線的遊戲不包裝成已可兌現價值 |
| 存檔與恢復 | 基礎登入存檔、已購恢復、跨裝置權益校對 | 不把避免資料遺失當作額外付費能力 |

### 支持者方案的候選設計

建議先只設計一種平台支持者，減少重複收費與權益混亂。售價、付款週期、自動續期方式與最終權益尚未決定。販售前需列明：

- 每項權益的適用遊戲、開始與結束時間。
- 哪些物品取得後保留，哪些只在會員有效期間使用。
- 到期後的畫面與權益處理，不移除免費核心內容。
- 付款、取消及恢復的真實操作流程。

這些是未來商業功能的必要設計，不表示目前已經有付費會員。

## 5. 廣告策略與通路邊界

### 自有網站

廣告合作方尚未選定。評估時需確認能服務我們的網域、瀏覽器與目標地區，並驗證無廣告、廣告阻擋、載入失敗與中途取消的流程。

單人獎勵優先選擇短期外觀試用或裝飾，不使用強制復活、不刻意製造等待。玩家看到的是「看廣告可得到什麼」與同樣清楚的「繼續遊玩」選項。

獎勵只依廣告方確認完成的事件發放；同一回呼不得重複領取。廣告有效付費曝光與獎勵完成是不同資料，營收以實際報表認列，不以按鈕點擊數估成真實收入。

### 第三方遊戲平台

Poki／CrazyGames 可作為獨立發行通路的候選，不能視為已合作。CrazyGames 官方文件指出一般自有網域的 SDK 環境為 disabled；不能將 SDK 放進 SnowRealmGames 就聲稱已有其廣告收入。［2］［3］

若未來發行到第三方平台，需單獨確認上架、品牌呈現、帳號、廣告、購買與回報要求。自有站收入與通路收入分開記帳，避免重複計算同一曝光或交易。

## 6. 收入模型

本節與 `unit-economics.json` 僅供內部敏感度演算。**所有範例人數、比例、售價及 eCPM 都是假設，不是預測、市場標準或正式開價。**

### 變數與口徑

| 變數 | 定義 |
| --- | --- |
| M | 平台去重後的月活躍使用者；玩兩款仍算一人 |
| Ns | 當月實際付費的支持者人數 |
| Ps | 支持者當月單價 |
| Oc | 當月外觀付費訂單數 |
| Pc | 外觀平均每筆實收金額 |
| I | 廣告方認列的有效付費曝光數 |
| E | 發行者端淨 eCPM；若已扣平台分成，不再重複扣除 |
| D | 實際退款、金流費、通路分潤與其他不重疊的交易扣款 |
| C | 伺服器、人力、內容、客服、推廣等營運成本 |

商品 gross 使用折扣後、退款前且排除代收款的同一口徑。廣告商投放總額不是我們的 gross，表內只計發行者可取得的廣告淨收入。

```text
商品銷售 gross = Ns × Ps + Oc × Pc
廣告淨收入 = I ÷ 1,000 × E
淨營收（本規劃口徑）= 商品銷售 gross − D + 廣告淨收入
營運結果 = 淨營收 − C
```

支持者可能同時購買外觀，兩筆收入可以相加，但不能將該玩家算成兩名獨立付費者。正式儀表板另計去重付費人數。

### 三個月度假設情境

純為方便算式，統一假設支持者 NT$100／月、外觀平均訂單 NT$150、發行者端淨 eCPM NT$60。這些數字不得直接填成公眾商店售價。

| 項目 | 小規模演算 | 中規模演算 | 較大規模演算 |
| --- | ---: | ---: | ---: |
| 平台 MAU | 1,000 | 10,000 | 50,000 |
| 付費支持者 | 10 | 200 | 1,000 |
| 支持者假設比例 | 1% | 2% | 2% |
| 外觀付費訂單 | 10 | 200 | 1,500 |
| 會員銷售 gross | NT$1,000 | NT$20,000 | NT$100,000 |
| 外觀銷售 gross | NT$1,500 | NT$30,000 | NT$225,000 |
| 商品銷售 gross 合計 | **NT$2,500** | **NT$50,000** | **NT$325,000** |
| 有效廣告曝光 | 1,000 | 20,000 | 150,000 |
| 廣告淨收入 | NT$60 | NT$1,200 | NT$9,000 |
| 扣實際交易費用後淨營收 | **NT$2,560 − D1** | **NT$51,200 − D2** | **NT$334,000 − D3** |
| 扣營運成本後 | **NT$2,560 − D1 − C1** | **NT$51,200 − D2 − C2** | **NT$334,000 − D3 − C3** |

沒有供應商報價、正式合約與實際帳單前，D 與 C 保持未知，不補造費率或「淨利」。未接廣告時，實際廣告收入為零；上述廣告情境僅用來理解未來敏感度。

### 成本必須拆開

- 固定／基本支出：基本運算服務、監控、必要訂閱等。
- 用量支出：即時房間、資料庫、儲存、CDN／傳輸與請求。
- 內容支出：角色、場景、音效、音樂、測試及更新。
- 人力支出：開發、維護、客服、社群；未支付薪資也應記錄投入工時。
- 推廣支出：素材、活動與獲客；不能把流量視為免費且無限。

成本歸類需避免重複：金流／通路扣款放 D，基礎設施與人力放 C。廣告分成若已包含在 E，不再放 D。

## 7. 階段與驗收

| 階段 | 交付範圍 | 驗收條件 |
| --- | --- | --- |
| A：可信的入口 | 真實遊戲狀態、旋界遊玩入口、企劃介紹 | 可玩與規劃中區分清楚；沒有假付款、假人數或假上線日期 |
| B：驗證回訪 | 旋界玩法與朋友房測試；收集裝置和再戰資料 | 能說明玩家在哪裡離開、為何再戰；不將測試目標寫成成果 |
| C：商品準備 | 完成一組外觀、權益清單與免費／付費邊界 | 商品在目標裝置可預覽、實際可用、無競技優勢 |
| D：權益與金流測試 | 真實服務的測試環境；尚不對外收款 | 成功、失敗、重複回呼、取消、到期與恢復皆不誤發權益 |
| E：小規模販售 | 僅販售已完成且明碼的商品 | 價格已確認；交易與權益可核對；客服能處理購買問題 |
| F：廣告試點 | 單人自願獎勵，實際廣告合作環境 | 不打斷多人；無填充／失敗仍能遊玩；報表區分請求與收益 |
| G：擴大內容 | NEXT FLOOR 垂直切片、52 HUNT 分階段驗證 | 各自先完成可玩的循環，再加入對應商品；不預售未知交付 |

以上不是時程承諾。通過產品及技術驗收後，才決定是否進入下一階段。

## 8. 實作與對外呈現守則

- 未啟用金流時，商品資料的售價與 checkout 狀態保持未設定／停用；不得由內部情境檔自動生成商店。
- 需要展示商業方向時使用「規劃中，尚未販售」，不用「訂閱成功」「購買完成」等假狀態。
- 正式權益由伺服器對照有效交易建立；localStorage 可保存介面偏好，不可作為付費證明。
- 收款前完成付款與權益的重複處理防護，避免回呼重送造成重複發放。
- 外觀與會員每次變更都保留版本，確保購買者知道當時買到什麼。
