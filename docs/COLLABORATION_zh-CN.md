# 两个实现的独立开发与公平比较

此仓库是 SnowRealm Games / 旋界的 v0.4 实现。用户已明确确认：`cube1` 专属于本项目，`cube2` 专属于 Claude 的另一实现，两版分别独立部署。

## 仓库与部署边界

| 项目 | 归属与维护范围 | 发布方式 |
|---|---|---|
| [luffysky/cube1](https://github.com/luffysky/cube1) | 本项目的 SnowRealm Games / 旋界源码、文档、后端与构建流程 | 从 cube1 独立构建和部署 |
| cube2 | Claude 负责的另一实现 | 从 cube2 独立构建和部署，由其维护方管理 |

本项目只操作 `cube1`，不读取、修改或推送 `cube2`，不向 Claude 自动发送消息、代码或账号资料。两个仓库不互相覆盖、不自动合并，不把一版的部署结果当作另一版的交付。当前也不共享生产数据库、钱包、排位池、支付密钥或其他秘密。

后续如需交流，仅在用户明确授权具体内容与目标后再安排；使用经审核的公开接口说明或脱敏测试数据，代码改动通过各自仓库的独立分支和 pull request 审查。

## 可供后续讨论的接口（默认不跨仓库同步）

- `dist/platform/catalog.mjs`：金币规则、商品 ID、免费外观、段位与建议订阅价格。
- `server/api` 与 `docs/BACKEND_API_zh-CN.md`：身份、钱包、幂等购买、好友、排位和签名权益事件。
- `dist/games/spinrealm/engine.mjs`：当前方块、SRS、锁定、计分与攻击规则；同一随机序列不意味着不同规则实现自动兼容。
- `dist/games/spinrealm/locales`：五语界面与占位符。
- `tests/api`、`tests/spinrealm` 与其他 `tests` 文件：行为验证。先跑测试再讨论替换实现。

## 接入要求

当前两版独立运行，cube1 的 Neon Auth、API 和数据库只服务本项目；不得自动把 cube2 的站点加入允许来源或接入现有钱包与匹配池。未来若用户另行决定共享账号体系，应先明确账号归属、数据隔离、授权范围与迁移方案，再登记正式站点 origin。客户端只能拿公开 Auth/API URL，不得获取数据库连接串或支付通知密钥。每次购买携带稳定的 Idempotency-Key；断线后先查状态，不重复扣款。

排位服务器是唯一权威。客户端只提交合法动作与递增序列，不能提交自己计算的金钱、段位或胜利。另一版如改变旋转、锁定、攻击表或随机规则，应另设 ruleset/匹配池；完成协议一致性测试前不要混配。

私人自订图片按账号保存在本机，不能将另一人的缓存当作公共素材。公开昵称必须转义；昵称不能作为翻译字典键。

## 比较实验

给两版明确的 build ID 与不同分发链接，在同一周期内交叉分配相近的新用户；记录设备、语言、来源、是否回访。观察第二局开局率、留存、比赛完成率、排队时间、操作延迟、反馈和收入，不只比累计访问量。

两个 Steam 产品应明确说明实际差异，先向 Steamworks 核实高度相似发行的处理方式。不能以奖励换评价、互刷评价或将相同玩家重复计算成新增用户。商业决策应由玩家行为和实测决定，不能因为由哪个助手编写就预设输赢。
